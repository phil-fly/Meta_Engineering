# Implementation Delivery Gate

本参考只在用户要求开发 handoff、实现摘要、PR 标题或 PR 描述时读取。先按 `final-state-delivery.md` 得到目标 `Scope/Version` 的当前需求状态，再核对实际实现；diff 只能证明做了什么，不能证明应该做什么。

## 变更分类

- **产品范围变更**：用户可见行为、业务规则、权限、数据契约/保留、外部 API、验收、安全/合规、迁移或回滚语义。必须映射到当前需求。
- **实现支撑变更**：可证明行为保持的测试、内部重构、格式化或非契约构建产物。必须映射到被支撑需求、实际 diff 和验证结果。

迁移、依赖升级、日志/监控和生成文件不是自动豁免项。触及数据、权限、安全、外部契约、迁移/回滚或可观察产品语义时按产品范围处理；无法证明行为保持时标记 `blocking`。

## 实现状态

| 状态 | 判定 |
| --- | --- |
| `Not assessed` | 未读取实际变更或验证结果 |
| `Implemented` | 已找到对应实现，但验证不足 |
| `Verified` | 产品能力均有当前需求依据、实现证据和通过的验证 |
| `Needs revision` | 存在范围偏差、失败验证或无法证明行为保持的支撑变更 |

需求为 `Ready for development` 不会自动提升实现状态。只有实现状态为 `Verified` 时，才能声称最终实现已完成。

## 核对流程

1. 读取当前需求交付中的 `Scope/Version`、`Requirement ID`、确认来源和 pending。
2. 读取实际 diff、相关测试及验证结果；无法读取时保持 `Not assessed`。
3. 把每项用户可见或契约性变更映射到当前需求，把内部支撑变更映射到被支撑需求。
4. 发现未确认产品能力时标记“范围偏差”，停止最终实现摘要。
5. 逐项核对失败验证、残余风险和回滚影响，再确定实现状态。
6. 从最终差异、需求依据、验证结果和现存风险生成标题、handoff 或 PR 文案。

## 可执行验收

- 产品能力声明都有 `Requirement ID`、当前需求来源、diff 证据和验证结果。
- 实现支撑声明都有被支撑需求、diff 证据和验证结果。
- 未映射产品能力、未验证实现声明和未说明失败验证均为 0。
- 标题与摘要不包含已撤回能力、纠错过程或仅存在于历史中的方案。

## 失败处理

- diff 或验证结果不可得：需求 handoff 可以定稿，实现保持 `Not assessed`。
- diff 含未确认产品能力：实现为 `Needs revision`；撤回越界变更，或由用户确认后更新当前需求状态。
- 无法证明支撑变更行为保持：按 `blocking` 处理，不得包装成内部无影响变更。
- 验证失败：保留失败证据与风险，不得标记 `Verified`。

## 人工回归

| 场景 | 预期结果 |
| --- | --- |
| PRD 已 Ready、尚未读取代码 | 需求为 `Ready for development`，实现为 `Not assessed` |
| diff 含未确认产品能力 | 实现为 `Needs revision`，不生成最终实现摘要 |
| diff 只含测试和行为保持重构 | 可作为实现支撑交付，不包装成新产品能力 |
