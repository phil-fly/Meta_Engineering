# 交互式决策协议

定义 AI Agent 协作中需要用户交互式选择的场景、选项设计标准和降级策略。

## 适用范围

本文件是 `product-requirements-partner` 的安装态运行时投影，仅包含产品需求协作所需的交互场景。跨技能编辑真值源位于源码仓根级共享参考；发布时由同步脚本核对本投影。

## 设计原则

1. **关键决策必须交互**：影响长期协议、目录结构、真值源的决策使用交互式选择
2. **选项互斥清晰**：每个选项有明确的后果说明，不产生歧义
3. **提供推荐项**：标记推荐选项，降低认知负担
4. **支持降级**：环境不支持时降级为文本问询，保持功能可用

## 交互式场景清单

### product-requirements-partner

#### 场景 5: 协作强度选择

**触发时机**：用户首次使用 skill 讨论产品想法，且未明确是否要落盘

**选项设计**：
```
header: "协作模式"
question: "选择本次协作模式"
options:
  1. 轻量讨论 (推荐 - 早期探索)
     描述: 自由讨论，不创建文件，适合快速验证想法
  2. 产物沉淀
     描述: 生成 PRD、设计文档等文件，适合明确需求后
  3. 项目记忆模式
     描述: 读取并更新项目记忆，适合长期协作项目
```

**决策依据**：
- 用户明确程度
- 是否存在项目记忆
- 是否把交付物作为本轮产出物索取（仅提及 "写文档"、"PRD" 等名词不算）

---

#### 场景 6: 目标目录选择

**触发时机**：需要初始化产品产物目录，且项目中无既有结构

**选项设计**：
```
header: "产物目录"
question: "选择产品产物的存放位置"
options:
  1. ai-agent-workspace/product/ (推荐 - 新标准)
     描述: 统一产物目录，与协议包同级，便于管理
  2. docs/
     描述: 传统文档目录，适合已有 docs/ 结构的项目
  3. 自定义路径
     描述: 指定其他路径（需要手动输入）
```

**决策依据**：
- 项目既有目录结构
- 团队协作习惯
- 是否采用统一产物布局

---

#### 场景 7: Scene 跳转确认

**触发时机**：用户请求跳过某个 Scene，但可能影响后续步骤

**选项设计**：
```
header: "Scene 跳转"
question: "Scene 2（流程与范围）尚未完成，是否跳转到 Scene 3（交互结构）？"
options:
  1. 先完成 Scene 2 (推荐)
     描述: 确保关键用户旅程明确后再设计页面结构
     理由: Scene 3 依赖 Scene 2 的旅程定义
  2. 跳转到 Scene 3
     描述: 使用现有信息先设计页面，旅程可后补
     风险: 可能需要回头修改页面结构
  3. 暂停，让我补充信息
     描述: 提供 Scene 2 缺失的关键信息后再继续
```

**决策依据**：
- Scene 依赖关系
- 缺失信息的关键程度
- 用户时间安排

---

#### 场景 8: [Meta] 层级判断

**触发时机**：用户使用 `[Meta]` 但未指定层级，且规则归属不明确

**选项设计**：
```
header: "Meta 层级"
question: "这条规则应该沉淀到哪里？「以后价值发现先让我自由讲 5 分钟」"
options:
  1. Layer 0 - 技能方法 (推荐)
     描述: 修改 product-requirements-partner 的 Scene 1 流程
     影响: 所有使用此技能的项目
  2. Layer 1 - 个人偏好
     描述: 记录到用户个人协作偏好
     影响: 您的所有项目，但不影响其他用户
  3. Layer 2 - 项目约定
     描述: 记录到当前项目记忆
     影响: 仅当前项目
  4. 仅本次生效
     描述: 本轮对话遵守，不持久化
     影响: 无持久化影响
```

**决策依据**：
- 规则的可复用性
- 规则的普适性
- 用户明确程度

## 选项设计标准

### 必需字段

```markdown
header: "分类标签"        # 简短（≤12 字符），如 "模型入口"、"生成模式"
question: "完整问题"      # 清晰具体，以问号结尾
options: [
  {
    label: "选项名称",         # 1-5 词，简洁
    description: "选项说明",   # 后果、适用场景、影响范围
    preview: "可选预览内容"    # ASCII mockup、代码片段、目录结构等
  }
]
```

### 推荐项标记

在 `label` 末尾添加 `(推荐)` 或 `(推荐 - 原因)`：

```
label: "项目版 (推荐)"
label: "CLAUDE.md (推荐 - 当前为 Claude 环境)"
```

### 后果说明

每个选项的 `description` 应包含：
- **适用场景**：什么情况下选这个
- **后果/影响**：选择后会发生什么
- **风险/注意事项**：可能的问题（如果有）

### 预览内容使用场景

使用 `preview` 字段当：
- 需要展示目录结构对比
- 需要展示代码片段差异
- 需要展示配置文件差异
- 需要展示 UI 布局对比

**示例**：
```
preview: |
  ai-agent-workspace/
  ├── protocols/
  │   ├── user/AGENTS.md
  │   └── project/AGENTS.md
  └── product/
```

## 降级策略

### 优先级

1. **原生交互式选择**（AskUserQuestion）- 优先使用
2. **结构化文本问询** - 降级方案 1
3. **普通文本问询** - 降级方案 2

### 降级条件

**触发降级**：
- 工具不可用（环境不支持 AskUserQuestion）
- 选项数量超过限制（> 4 个）
- 需要多选而工具不支持

**降级格式**：

```markdown
## 模型入口选择

请选择协议入口文件（将作为 AI 模型的发现入口）：

1. **CLAUDE.md** (推荐 - 当前为 Claude 环境)
   - 适用于 Claude Code / Anthropic 工具链

2. **AGENTS.md**
   - 通用入口，适用于 Codex/OpenAI 及其他工具

3. **保留既有 {existing-entry}**
   - 继续使用根级现有入口，不创建新文件

请回复数字（1/2/3）或选项名称。
```

## 用户体验目标

实施后的预期体验：

✅ **决策点清晰**：用户明确知道何时需要做选择
✅ **选项易懂**：每个选项的后果和影响一目了然

✅ **可回溯**：生成报告中记录所有交互式选择及依据
✅ **环境兼容**：在不支持交互式工具的环境中降级为文本问询
