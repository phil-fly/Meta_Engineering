# 主流程仲裁

当一个请求同时命中创建、维护、升级同步、转换、规则摄入、一般审查、触发稳定性审查或协议工程时，使用本契约选出唯一主流程。

## WF-PROTOCOL-ROUTING

输入是用户最终交付物、是否授权写入、目标资产是否已存在以及审查维度；输出必须是一个主流程和零到多个辅助流程。

### Checkpoint 1：判断写入意图

- 用户要求创建、修改、合并、同步、迁移、修复或落盘时，属于写入任务。
- 用户只要求解释、评估、审查、比较或给建议时，属于只读任务。
- 同一请求同时包含审查和修复时，属于写入任务；审查只负责形成修改依据。

### Checkpoint 2：选出唯一主流程

写入任务按最终交付物仲裁：

| 条件 | 主流程 | 辅助流程示例 |
| --- | --- | --- |
| 新建协议、入口或协议包 | 创建 | 转换、规则摄入、触发稳定性审查 |
| 对照新版规则同步既有协议包 | 升级同步 | 协议工程、触发稳定性审查 |
| 修改、合并、修复或重构既有资产 | 维护 | 规则摄入、协议工程、触发稳定性审查 |
| 把零散内容整理为新结构，且未要求并入既有资产 | 转换 | 规则摄入 |
| 只判断新规则的类型、维护位置或触发入口 | 规则摄入 | 一般审查 |

若要求把新规则直接合并进既有资产，主流程是维护，规则摄入是辅助流程。若创建任务需要整理零散输入，主流程是创建，转换是辅助流程。

只读任务按以下优先级选主流程：

1. 明确检查触发链、条件路由、约束门禁或检查项映射时，主流程是触发稳定性审查。
2. 否则，明确检查执行率、复杂度、冲突、Token 成本或长期维护性时，主流程是协议工程。
3. 其余只读评估以一般审查为主流程。

一般审查、触发稳定性审查和协议工程在写入任务中只能作为辅助分析维度，不能与写入主流程并列。

### Checkpoint 3：处理仍未消除的冲突

- 用户明确指定的最终交付物优先于关键词推断。
- 目标资产是否存在只用于区分创建、升级同步和维护，不改变用户明确要求。
- 仅当候选主流程会导致不同写入范围、覆盖策略或真值源迁移，且现有证据无法裁决时，才在写入前询问用户。
- 问询必须列出候选最终交付物及各自写入范围，例如“本次以修复既有协议为交付物，还是只输出审查报告？”，不得只问笼统的“如何继续”。
- 如果不存在写入授权或询问工具不可用，保守降级为只读审查并明确未执行写入。

### Checkpoint 4：声明并继承路由

- 首次进度说明和最终回复都应声明主流程；存在辅助流程时一并声明。
- 后续层级判断、参考文件选择、修改范围、验证和闭环必须继承该主流程，不得在中途因新增关键词静默切换。
- 若用户后续明确改变交付物，重新执行本仲裁并说明路由变化。

## 失败条件

以下任一情况表示路由未闭环：

- 输出了两个或更多并列主流程。
- 写入任务以审查维度代替创建、升级同步、维护或转换主流程。
- 主流程变化后没有重新确认修改范围和真值源。
- 因路由不确定而直接扩大写入范围。

发生失败时，停止扩大修改范围，回到 Checkpoint 1；已经形成的发现保留为待处理证据，不得无故丢弃。
