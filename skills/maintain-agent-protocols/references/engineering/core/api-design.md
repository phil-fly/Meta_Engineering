# Api Design

适用后端接口、前后端契约、列表查询和响应格式。

核心规则：

- API 必须暴露稳定且可演进的契约，新增字段或行为变化应考虑兼容性。
- 业务响应应使用一致结构，业务失败应返回稳定错误码和可操作消息。
- 查询接口必须先分类：分页列表、小集合列表、枚举/字典列表、远程搜索、统计列表或导出列表。
- 分页列表必须显式分页，响应字段应稳定包含数据、总数、页码和页大小等语义；小集合或枚举列表可不分页，但必须说明数据上限、稳定性和刷新策略。
- 会影响结果全集的列表筛选、搜索、统计和排序必须由服务端完成，不允许前端伪造全量结果；仅作用于已加载小集合展示时，应说明数据上限和不会改变全集语义。
- 排序字段必须通过白名单映射，禁止直接透传底层字段、表达式或实现细节。
- Handler/Controller 只处理协议层职责，业务逻辑不得堆在接口入口。
- 接口变更必须说明调用方影响、兼容策略和验证方式。

验证与输出：

- 说明查询类型、响应结构、分页或不分页依据、筛选排序和兼容性。
- 说明前后端是否对同一契约有一致理解。
