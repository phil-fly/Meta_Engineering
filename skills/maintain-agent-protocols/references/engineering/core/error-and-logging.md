# Error And Logging

适用错误码、错误消息、日志、审计和诊断上下文。

核心规则：

- 业务失败必须使用稳定错误码，避免同一错误在不同层返回不同语义。
- 错误码必须区分传输失败、系统失败和领域失败。
- 用户错误消息必须可操作，不能只返回笼统失败。
- 面向用户的错误信息和面向开发者的日志上下文必须分离。
- 日志必须结构化，包含必要关联标识、操作结果和诊断字段。
- 日志不得包含密钥、令牌、密码、证书、连接串、敏感请求体或隐私数据。
- 安全相关操作必须产生可审计事件，并包含 actor、target、outcome 和 request id 等关键上下文。

验证与输出：

- 说明错误码稳定性、用户消息可操作性、日志结构和脱敏处理。
