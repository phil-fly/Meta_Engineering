# 企业级产品设计（SaaS/安全/运维/管控台）

适用于网络安全产品、安全管控台、运维平台、云管平台、AI 平台、数据平台、网关设备管理系统、企业级 SaaS、管理后台和可视化控制台的产品设计、页面设计、交互设计、线框图和视觉稿生成。

不适用于官网首页、活动页、品牌宣传页、营销落地页、游戏化界面、概念稿或纯展示型视觉探索。

## 核心约束

- CON-FE-SAAS-001 产品建模优先：从需求生成或重构企业级控制台设计时，必须先理解系统本质，输出系统类型、核心实体、用户角色、核心流程、辅助流程和关键状态；禁止直接从需求跳到视觉稿。验证方式是检查交付中是否先回答“用户真正管理的是什么”。
- CON-FE-SAAS-002 用户任务优先：页面和导航必须围绕用户目标、用户任务、业务流程和业务领域组织；禁止按数据库表、后端模块、API 分组或配置文件结构直接设计菜单和页面。验证方式是检查每个页面是否能映射到明确用户任务。
- CON-FE-SAAS-003 页面职责收敛：每个页面必须有明确页面目标、主要操作、次要操作、管理实体、关键决策、前置条件和后置结果；禁止把一个页面设计成无边界的万能操作台。验证方式是检查页面职责模板是否完整。
- CON-FE-SAAS-004 信息架构可解释：一级菜单、二级菜单、菜单职责、用户入口和核心操作必须可追溯到用户目标或业务流程；菜单项不足 10 个时优先 Tabs，不足 30 个时优先 Sidebar，30 个及以上应使用分类导航或分组导航。
- CON-FE-SAAS-005 线框图前置：生成视觉稿、Figma prompt 或高保真设计前，必须先输出页面结构和线框图；只有小范围样式修复、既有页面局部调整或用户明确跳过时可例外，并在交付中说明。禁止静默跳过设计阶段；用户明确只要局部产物时，必须保留必要前置结论并在交付中明确说明省略项和适用范围。
- CON-FE-SAAS-006 落地性优先：企业控制台设计应优先保证可开发、可维护、可扩展、高信息密度和高操作效率；禁止优先追求炫酷动画、未来风、营销式大 Banner、装饰性插画或概念稿效果。
- CON-FE-SAAS-007 数据规模优先：设计默认应支持 500+ 实体、1000+ 资源、500+ 规则和 10000+ 事件的管理场景；列表、表格、筛选、分页、虚拟化和横向滚动策略必须能解释如何承载规模，并符合 `CON-FE-SAAS-011` 的组件选型数量阈值要求。验证方式是检查在目标数据规模下页面是否保持可用性、性能和信息可达性。
- CON-FE-SAAS-008 状态语义一致：正常、告警、异常、停用和未知状态必须使用一致语义，并继承项目 Design Token；默认语义为正常绿色、告警橙色、异常红色、停用灰色、未知蓝灰色。
- CON-FE-SAAS-009 企业级视觉边界：默认浅色主题、弱阴影、8px 圆角、清晰边框、紧凑表格和数字等宽展示；禁止 Glassmorphism、Neumorphism、Cyberpunk、Futuristic UI、大面积渐变背景、无意义动态图、装饰性插画、游戏化界面和科幻风界面进入企业控制台主界面。
- CON-FE-SAAS-010 设计决策可追溯：所有布局、组件和视觉决策必须能追溯到用户目标、业务流程、页面职责或信息架构；不能只以个人审美偏好作为理由。
- CON-FE-SAAS-011 组件选型数量阈值：数据展示数量少于 20 条时使用 Table 或紧凑列表；20 到 200 条时使用 Card、Table 或分组视图；超过 200 条时必须使用 Virtual Table、分页、服务端筛选或批量操作；导航项不足 10 个时使用 Tabs，不足 30 个时使用 Sidebar，30 个及以上必须使用分类导航或分组导航。验证方式是检查组件选型与数据规模的映射关系。

## 标准输出

企业级 SaaS 设计任务默认按以下顺序输出：

```text
1. 产品建模
2. 信息架构设计
3. 页面职责分析
4. 页面布局设计
5. 组件规划
6. 页面线框图
7. 视觉设计 Prompt
8. 高保真设计稿或前端实现说明
```

默认不得跳过任意阶段。若用户只要求其中一部分，应保留必要前置结论，并在交付中明确说明省略项、适用范围和剩余风险。

## 产品建模模板

```yaml
系统类型:
核心实体:
用户角色:
核心流程:
辅助流程:
关键状态:
用户真正管理的对象:
```

判断“用户真正管理的对象”时，应从生命周期、运行环境、事件闭环、策略生效、资源关系和风险处置角度重新表达，不停留在表名或对象名。

## 信息架构模板

```yaml
一级菜单:
二级菜单:
菜单职责:
用户入口:
核心操作:
```

常见企业控制台结构可参考：

```text
总览
资源管理
服务管理
配置管理
巡检中心
审计中心
系统设置
```

菜单名称应按业务领域和用户任务收敛，不按后端目录或 API 分组平移。

## 页面职责模板

```yaml
页面名称:
页面目标:
主要操作:
次要操作:
管理实体:
关键决策:
前置条件:
后置结果:
```

页面职责用于决定布局、组件和操作区，而不是交付后的补充说明。

## 布局模式

- Dashboard：Header、KPI 指标区、分析区、健康度区和事件区；适合总览、态势、运行健康度和风险监控。
- 管理页面：左侧导航、中间工作区、右侧操作区；适合资产、设备、服务、资源、策略和规则管理。
- 编辑页面：基础信息、运行配置、依赖关系、高级配置和配置预览；适合配置型、策略型和资源编排型页面。
- 巡检中心：健康度概览、问题统计、问题列表和修复建议；适合运维、安全、设备和资源健康检查。

布局必须由业务流程推导；无法说明页面职责时，不应先确定布局。

## 组件选型

按 `CON-FE-SAAS-011` 的数量阈值要求：

- 数据展示数量少于 20 条时使用 Table 或紧凑列表；20 到 200 条时使用 Card、Table 或分组视图；超过 200 条时必须使用 Virtual Table、分页、服务端筛选和批量操作。
- 导航项不足 10 个时使用 Tabs；不足 30 个时使用 Sidebar；30 个及以上必须使用分类导航或分组导航。
- 单层关系使用 List；树状关系使用 Tree；复杂关系使用 Graph、拓扑图或依赖关系图，并提供列表兜底。
- 安全、运维和云管类产品优先考虑状态标签、健康度评分、风险卡片、配置校验面板、巡检面板、引用关系面板、拓扑图、依赖关系图、变更集、审计记录和操作时间线。
- 配置型界面优先考虑抽屉编辑器、YAML/JSON 预览器、配置 Diff、资源关系图、健康度仪表盘和变更确认。

组件选型必须同时读取 `compact-ui.md`、`ui-stability.md`、`component-system.md` 和 `accessibility.md` 中与任务相关的规则。

## 视觉基线

默认视觉基线：

```yaml
主题: 浅色
主色: "#3b82f6"
成功: "#10b981"
告警: "#f59e0b"
危险: "#ef4444"
背景: "#f8fafc"
卡片: "#ffffff"
边框: "#e5e7eb"
文字: "#111827"
辅助文字: "#6b7280"
圆角: 8px
阴影: 极弱阴影
目标分辨率: 1920x1080
最小支持宽度: 1280px
```

字体规范：

```yaml
标题: SemiBold
正文: Regular
表格: Compact
数字: Monospace
辅助文字: Regular
```

如项目已有 Design Token 或组件库主题，必须继承项目现状；以上基线只能作为缺少项目标准时的默认参考。

目标分辨率和浏览器缩放验证要求继承 `ui-stability.md` 的 `CON-FE-STABILITY-002` 和 `CON-FE-STABILITY-003`。

## 视觉稿 Prompt 要求

生成视觉稿 Prompt 时，应包含企业级 SaaS、生产可落地、高信息密度、真实产品界面、组件化设计、Design System、运维控制台、管理平台、专业化、可扩展和生产环境可用等目标词。

可参考阿里云控制台、腾讯云控制台、华为云控制台、VMware vCenter、Rancher、Portainer、Kubernetes Dashboard、Grafana、Datadog 和 Elastic Kibana 的信息密度、导航组织和组件模式，但不得复制具体品牌视觉或专有界面。
