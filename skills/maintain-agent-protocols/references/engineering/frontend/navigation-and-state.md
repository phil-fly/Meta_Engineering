# 前端导航与路由状态

## 核心规则

- 页面功能入口应在两层内闭合；二级入口切换时应清理无关 query 和路由状态。
- 配置型、治理型或工作台型模块应优先采用一级入口加二级快捷入口的双层导航模型。
- 二级导航应从一级导航右侧贴边展开，避免默认通过居中弹窗、遮罩模态或压缩工作区宽度的方式承载。
- 二级快捷入口必须落到真实页面边界、稳定 tab 或稳定子工作区，而不是只把用户送回一级页面继续寻找。
- 多模块二级导航应优先使用集中式导航注册表维护入口、分组、搜索关键字、默认入口和页内落点映射。
- 文件命名必须与真实职责一致，避免组件名、文件名和实际行为漂移。
- 复杂页面状态、服务端缓存、表单状态和 URL 状态的拥有者规则以 `state-and-cache.md` 为准；本文件只补充导航入口与路由参数的可达性。
- 注释规范继承 `../core/common-quality.md`；本文件只补充前端导航、路由状态和页面状态规则。
- 异步生命周期、缓存失效和过期响应以 `state-and-cache.md` 为准。
- 页面改造前必须确认真实挂载入口、路由和宿主视图，避免只改未接线组件。

## 输出要求

- 说明页面入口、导航层级、路由参数、落点映射和真实挂载位置。
- 如涉及共享状态、URL 状态或异步状态，同步给出 `state-and-cache.md` 的处理结论。
