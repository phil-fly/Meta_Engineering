# Design Token

适用产品 UI 样式、主题色、品牌色、状态色、中性色、边框、背景和文本颜色的新增或修改。

## 核心规则

- 产品 UI 颜色应优先通过 Design Token、主题变量或项目既有语义变量使用，避免在组件和页面内直接硬编码颜色值。
- 品牌色、状态色和中性色必须具备明确语义，例如 primary、success、warning、danger、info、text、border、background、muted。
- 新页面应优先复用现有 token 或语义变量，不新增同义颜色；确需新增时，应说明语义、适用场景和与既有 token 的差异。
- 修改页面时只处理本次改动范围内的颜色和视觉问题，避免借机进行全局视觉重构。
- 状态色必须保持语义一致；成功、警告、危险和信息色不得在同一项目内表达相互冲突的状态。
- 仅当项目尚未建立 token 体系时，可临时使用既有 CSS 变量、设计系统变量或局部语义变量；不得把一次性颜色扩散成公共约定。
- 图表色、品牌插画、第三方嵌入、截图复刻和临时调试色可作为例外，但应说明原因，且不应污染通用 UI token。

## 输出要求

- 说明本次颜色来自哪个 token、主题变量或语义变量。
- 说明是否新增 token；若新增，说明语义、适用场景和与既有 token 的差异。
- 说明状态色是否保持 success、warning、danger、info 等语义一致。
- 说明是否只处理本次改动范围，未进行无关全局视觉重构。
