# 前端状态与缓存

适用组件状态、应用状态、服务端缓存、表单状态、URL 状态、路由状态、筛选分页状态和异步生命周期管理。

## 状态分类

```text
组件状态      → 只影响局部组件展示和交互，默认靠近使用处
应用状态      → 主题、全局弹窗、登录用户、通知等跨页面状态
服务端缓存    → 从接口获取并需要刷新、失效、预取或重试的数据
表单状态      → 字段值、校验结果、dirty/touched、提交中和服务端错误
URL 状态      → query、path param、tab、分页、筛选、排序和可分享上下文
```

## 核心约束

- CON-FE-STATE-001 状态拥有者：每个状态必须有唯一主拥有者；不得在组件、store、URL、query/cache 和本地存储之间维护无同步策略的平行状态。
- CON-FE-STATE-002 近源管理：组件局部状态默认留在使用处；只有跨层共享、跨页面保持、URL 可分享或服务端缓存复用时，才提升到更高层级。
- CON-FE-STATE-003 服务端缓存：接口数据默认由 query/cache 层或项目既有数据加载层管理；不得为了方便把服务端数据长期复制到全局 store，除非说明失效、刷新和一致性策略。
- CON-FE-STATE-004 URL 同步：分页、筛选、排序、tab 和搜索词如果影响可分享结果或浏览器回退，必须明确 URL 与 UI 状态的初始化、更新、重置和清理关系。
- CON-FE-STATE-005 异步生命周期：异步状态必须覆盖 loading、error、success、empty、cleanup、取消或过期响应；路由切换、组件卸载和条件变化时不得留下悬挂更新。
- CON-FE-STATE-006 缓存失效：创建、更新、删除、批量操作和导入导出完成后，应明确影响哪些 query、列表、详情、统计或本地派生状态，以及如何失效或刷新。
- CON-FE-STATE-007 本地持久化：localStorage、sessionStorage、IndexedDB 和 Electron 本地存储只保存适合客户端持久化的数据；生产密钥、长期令牌和权限裁决不得保存在浏览器端。

## 输出要求

- 说明本次状态属于组件、应用、服务端缓存、表单还是 URL 状态。
- 说明状态主拥有者、初始化来源、更新路径、清理时机和缓存失效策略。
- 说明是否存在平行状态、过期响应、无界缓存、悬挂更新或客户端权限误用。
