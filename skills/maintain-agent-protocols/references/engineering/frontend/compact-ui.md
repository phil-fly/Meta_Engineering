# Compact UI

适用管理后台、SaaS、数据看板、配置页、表单页和高频操作页的布局密度、首屏信息组织和视觉空间调整。

## 核心规则

- Compact UI 的目标是优先保证核心任务、主要操作和关键反馈在首屏可见；不得为了压缩高度牺牲可读性、可点击性或可访问性。
- 应减少无效高度，例如重复标题、空容器、过大的 header、过厚卡片 padding 和无信息分隔区。
- 删除重复文案和弱价值说明；保留会影响判断、风险理解、操作结果或合规要求的信息。
- 标签和值优先单行展示；字段值较长、需比较或需辅助阅读时，可换行但应保持扫描节奏。
- 短选项优先横向布局；选项较长、数量多或移动端空间不足时，应改为纵向或响应式布局。
- Tooltip 用于补充信息、解释边界或展示次要帮助，不重复标题、label 或按钮文案。
- 优先减少嵌套层级和装饰性容器，避免卡片套卡片、标题套标题和重复分组。
- 优先压缩外围容器、说明区、筛选区和工具栏的占用，不压缩核心内容、关键表格、表单输入区和主要图表。
- 图表页面应优先保证图表区域高度、图例可读性和关键指标可见；不要让说明区或筛选区挤占主要图表。
- 页面留白节奏应保持一致；局部压缩后仍应维持可读的间距体系和对齐关系。

## 输出要求

- 说明本次页面的核心任务、主要操作和首屏可见性结论。
- 说明压缩的是外围容器、说明区、筛选区、工具栏还是核心内容，并解释取舍。
- 说明是否删除重复文案、弱价值说明、重复 tooltip 或多余嵌套层级。
- 涉及图表页面时，说明图表区域高度、图例和关键指标是否得到优先保障。
- 说明紧凑化是否保持可读性、可点击性、可访问性和留白节奏一致。
