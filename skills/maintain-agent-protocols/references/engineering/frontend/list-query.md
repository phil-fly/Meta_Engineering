# 前端列表查询接口

前端列表、表格、下拉数据源、枚举列表、选择器和搜索结果相关任务先读本文件。

本文件是组合路由，只聚合必读入口和分类策略；具体规则仍以对应路由文件为准。

## 必读入口

- 前端请求与数据加载：读取 `api-and-data.md`。
- 接口契约：读取 `../core/api-design.md`。
- 通用质量：读取 `../core/common-quality.md`。

按条件补读：

- 涉及权限、租户、资源归属或菜单可见性：读取 `../core/auth-and-permission.md`。
- 涉及用户输入筛选、排序字段、资源 ID 或批量条件：读取 `../security/index.md`。
- 涉及大数据量、复杂查询、统计、导出或性能目标：读取 `../performance/index.md`。
- 涉及表格列宽、长文本列、横向滚动、极限数据或运行态 UI 验收：读取 `ui-stability.md`。

## 查询类型分类

```text
分页列表      → 数据量可能增长、面向表格/管理列表/搜索结果，必须服务端分页
小集合列表    → 数据量稳定且有明确上限，可不分页，但必须说明上限和缓存策略
枚举/字典列表 → 稳定少量选项，可一次加载，但应有版本、失效或刷新策略
远程搜索      → 用户输入驱动，必须服务端搜索、限制返回数量并处理防抖/取消
统计列表      → 涉及聚合或总数，统计口径必须由服务端定义
导出列表      → 不等同分页查询，必须单独确认权限、范围、异步和审计策略
```

## 核心约束

- 不要把“列表”默认等同为“必须分页”；先判断查询类型、数据规模和增长风险。
- 只要筛选、搜索、排序、统计会影响结果全集，就必须由服务端能力支撑。
- 小集合或枚举列表可以不分页，但不得通过前端当前页数组伪造全量筛选、排序或统计。
- 排序字段、筛选条件、分页整数、资源 ID 和批量条件属于不受信输入，必须服务端校验或白名单映射。
- 前端控件必须反映真实后端能力；后端不支持时应隐藏、禁用或明确标记不可用。
- 筛选条件变化时应重置分页；远程搜索应处理 loading、error、success、cleanup 和过期响应。

## 输出要求

- 说明本次查询属于哪一类。
- 说明是否需要分页；若不分页，说明上限、稳定性和缓存/刷新策略。
- 说明筛选、搜索、排序、统计是否由真实后端能力支撑。
- 说明权限、输入校验、排序白名单和性能风险是否覆盖。
- 涉及表格呈现时，说明列宽、长文本查看、横向滚动和极限数据验证是否覆盖 `ui-stability.md`。
