# 前端性能

适用首屏加载、路由级 code splitting、bundle 体积、图片和字体、预取、渲染频率、运行时样式成本、Web Vitals 和前端性能验证。

## 核心约束

- CON-FE-PERF-001 指标先行：前端性能优化必须先说明目标指标、关键路径和验证方式；不得用无证据微优化替代真实瓶颈分析。
- CON-FE-PERF-002 路由级拆分：大型前端应用应优先在路由、业务模块或低频重组件边界做 code splitting；不得为了拆分而制造过多小 chunk 或破坏关键路径。
- CON-FE-PERF-003 资源体积：新增组件库、图表库、编辑器、地图、运行时样式方案或 polyfill 时，应说明体积影响、加载时机和替代方案。
- CON-FE-PERF-004 图片字体：图片、图标、字体和媒体资源应具备尺寸、格式、懒加载、预加载或响应式策略；不得让非首屏大资源阻塞核心任务。
- CON-FE-PERF-005 渲染边界：高频更新、长列表、复杂图表和全局状态变化应明确渲染范围、虚拟化、节流防抖或选择器策略；不得用全局状态触发无关页面重渲染。
- CON-FE-PERF-006 预取边界：数据或代码预取必须服务明确的下一步旅程；不得默认全局预取大集合、低频页面或无界缓存。
- CON-FE-PERF-007 样式运行时成本：高频更新或大规模列表场景应评估运行时 CSS-in-JS、动态样式生成和主题切换成本；项目既有方案优先，但性能热点需要证据化验证。
