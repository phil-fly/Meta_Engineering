# Deployment

适用部署工作区、runtime 组装、本地启停和清理策略。

核心规则：

- 仓库内应有清晰部署工作区入口；如仓库采用本地 deploy workspace，应优先使用专门的 `deploy/` 目录承载入口脚本、基础配置和运行时产物。
- runtime root 应自包含，能说明二进制、配置、静态资源和脚本组成；如采用约定式工作区，`deploy/runtime` 应包含可运行入口、配置资产、日志目录和运行状态目录。
- 部署入口应支持可重复生命周期动作；如采用统一入口脚本，应至少覆盖 build、runtime、start、stop、restart、status 和 clean。
- runtime 生命周期管理应保持工作区本地化，避免污染用户全局环境。
- clean 行为必须支持明确配置保留策略，避免误删重要配置。
- 默认部署参数和 runtime 映射应外置配置，避免硬编码环境差异；如项目使用基础配置文件，应集中收口运行时目录、日志/PID 路径、构建产物位置和 clean 默认策略。

验证与输出：

- 说明部署入口、runtime 组成、生命周期和清理策略。
