# Observability

适用日志、指标、链路追踪、审计事件和关联标识。

核心规则：

- 请求必须能跨服务边界追踪；缺少关联标识时应生成或补齐。
- 存在上游请求 ID 时必须保留并向下游传播；缺失时必须生成新的 request id，并写入结构化日志。
- 日志、指标、追踪和审计应使用稳定字段，支持跨系统对账。
- 安全相关操作必须产生审计事件。
- 审计事件应包含 actor、target、操作意图、结果和 request id；如项目定义了固定审计 sink，应说明落点。
- 观测数据不得泄露敏感信息。

验证与输出：

- 说明 request id、trace id、审计事件和敏感信息处理。
