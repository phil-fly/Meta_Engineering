# 场景手册

本文件是技能内场景流程的单一来源。落盘到目标仓时，先确认场景手册真值源：若选择 `ai-agent-protocols/playbooks/`，应按章节拆分为独立文件；若目标仓已有根级 `playbooks/` 并继续作为真值源，则协议包内只生成索引或别名说明，不复制完整正文。

## WF-CODING coding

开发任务默认流程：

1. 识别语言、工程域和风险等级。
2. 读取对应工程路由。
3. 检查是否涉及 API、数据结构、配置、权限、安全或架构边界。
4. 按最小修改实施。
5. 运行与变更范围匹配的验证。
6. 汇报变更、验证结果和剩余风险。

## WF-ARCHITECTURE architecture

架构任务默认流程：

1. 明确目标、约束、非目标和影响范围。
2. 读取相关工程路由和通用质量、安全、性能路由。
3. 对比可选方案及权衡。
4. 给出推荐方案、迁移影响和验证方式。

## WF-SECURITY-REVIEW security-review

安全审查默认流程：

1. 声明审查模式、范围、未覆盖范围和资产边界。
2. 读取 `common-security.md`、`auth-and-permission.md`、相关语言路由和相关业务路由。
3. 先盘点入口、数据流、身份、资源、敏感操作和外部依赖。
4. 按控制点审查，避免只凭漏洞直觉搜索。
5. 输出发现、证据、影响、修复建议和沉淀去向。

## WF-PERFORMANCE-REVIEW performance-review

性能审查默认流程：

1. 声明审查范围、关键路径和性能目标。
2. 读取 `common-performance.md`、相关语言路由、数据访问和可观测性路由。
3. 检查 N+1、资源泄漏、复杂度、对象分配、阻塞和缓存一致性。
4. 输出瓶颈、证据、优化建议、验证方式和风险。

## WF-TROUBLESHOOTING troubleshooting

故障排查默认流程：

1. 明确现象、影响范围、发生时间、复现条件和最近变更。
2. 收集日志、错误信息、配置、输入输出、环境差异和相关代码证据。
3. 基于证据提出可验证假设，避免一次性堆叠多个未知变量。
4. 按最小实验验证假设，每次只改变一个关键条件。
5. 定位根因后给出修复方案、回归验证方式和剩余风险。
6. 仅将可复用经验、长期规则或架构决策沉淀到协议、文档或 Wiki。

## WF-RESEARCH research

技术调研默认流程：

1. 明确调研问题、决策目标、约束、非目标和评估维度。
2. 优先收集官方文档、项目源码、标准、论文或一手资料。
3. 对比候选方案的适配性、成本、风险、维护性和迁移影响。
4. 区分已验证事实、合理推断和待确认信息。
5. 给出推荐结论、适用范围、验证建议和后续决策点。
