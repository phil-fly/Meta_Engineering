# 检查清单

## maintenance-checklist

- 规则是否有明确适用范围和维护位置？
- 用户协议是否只保留入口、优先级、任务分类和长期原则？
- 执行细节是否已下沉到 `routes/`、`playbooks/`、`checks/` 或 `templates/`？
- 约束是否写明适用范围、生效条件、规则正文和验证方式，而不是只留标签词？
- 协议包落盘前是否先给出生成方案预览，并经用户确认？
- 生成模式是否明确为最小版、项目版或完整版，且默认项目版没有生成无证据语言/框架路由？
- 项目事实、技术栈、命令和目录职责是否都有来源；无来源内容是否标为待确认？
- 项目级 `必须`、`禁止`、`默认` 或 `仅当` 是否都有目标仓证据支撑？
- 用户协议引用的入口文件是否实际存在？
- 是否已声明唯一生效入口和各资产真值源，避免根级目录与 `ai-agent-protocols/` 全文双写？
- 协议正文、协议包 README 和入口说明是否排除了“生成依据”、读取文件清单和事实来源清单？
- 生效协议、协议包 README 和入口说明是否清除了 `<project>`、`<install-command>`、`<path>` 等模板占位符？
- 是否单独提供生成报告，并把扫描过程、读取文件清单、置信度和使用者下一步放在报告而不是协议正文？
- 生成报告是否说明工作区状态，包括未跟踪文件和无关修改？
- 嵌套目录中的路径引用是否能按当前文件位置或声明的仓库根口径解析？
- 新增规则是否与更高优先级指令冲突？
- 如新增、移动或删除 reference，`SKILL.md`、局部 index 和总入口是否已同步？
- 发现的问题是否归类为已解决、延后处理、明确排除或转入后续任务？

## security-checklist

- 是否校验信任边界输入？
- 是否保护密钥和敏感日志？
- 是否有认证、授权和资源归属？
- 敏感操作是否具备审计和防滥用？
- 不受信选择器是否经过安全中介？
- 安全整数是否先校验再转换？
- 是否覆盖 OWASP Top 10 相关风险？

## performance-checklist

- 是否存在 N+1 查询？
- 是否存在未释放资源或长期持有对象？
- 是否存在高复杂度算法？
- 是否在循环中重复创建可复用对象？
- 是否存在关键路径同步阻塞？
- 是否说明性能验证方式？
